Best practices

How to get more out of Claude Code — starting with skills and slash commands, then session habits that improve quality and cut cost.

Skills & commands

A skill is a packaged capability Claude runs via the Skill tool, usually exposed as a /slash-command. Each one bundles domain knowledge plus a procedure — so instead of explaining how to review a diff or build a deck every time, you invoke the skill and it follows a vetted workflow.

Two ways to trigger one

  • Type the command — start a message with / and pick from the list (e.g. /qa, /review, /update).
  • Just describe the task — Claude auto-selects a matching skill when your request fits one (e.g. "make a slide deck" → the pptx skill).

Sessions & cost

This is the highest-leverage area. A session is one continuous conversation (one transcript file). How you manage it drives both quality and spend.

Keep sessions short and focused

One coherent unit of work, one project. Avoid week-long threads — they re-read a huge context on every turn (expensive) and compact repeatedly (lossy, lower quality).

Run /update, then /clear at natural stops

/update flushes your progress to disk (note + journal); /clear resets to a fresh context. The next session auto-loads the digest, so you resume informed without dragging the old history along.

Let stable context stay cached

Claude caches the front of your context. Stable, slow-changing material (CLAUDE.md, the digest) re-reads cheaply; a constantly-growing conversation does not. Small + stable beats big + complete.

Use plan mode for anything non-trivial

For refactors, migrations, or new features, plan first. You review the approach cheaply before any code is written, instead of correcting mid-flight.

The one rule: treat a session as disposable. Your memory now lives in the repo (note + journal + digest), so closing and starting fresh loses nothing — and it's the single biggest lever on both token spend and answer quality.

Knowledge & memory

Write it down at session end

/update appends a journal entry and rebuilds the auto-loaded digest. The next session starts knowing where things stand — no re-explaining.

Keep CLAUDE.md tight

It loads every session, so every token is recurring. Capture shape, conventions, key paths, and the gotchas that bite — not line-level detail (that rots).

Two tiers for tech docs

An always-on Architecture brief in CLAUDE.md plus an on-demand knowledge/architecture.md spec. Claude reads the deep one only when working in that area.

Let the code be the truth

Docs answer "shape, why, where." For "exactly how," Claude reads the actual code — so docs stay short and don't drift out of date.

General tips

  • Be specific, name the file. "Fix the auth redirect in src/auth/session.ts" beats "fix login." Concrete pointers cut exploration cost.
  • Ask for a plan before big changes. A short approach you can course-correct is cheaper than a wrong implementation.
  • Commit often. Claude reads git — clean checkpoints make diffs reviewable and let you roll back safely.
  • Bootstrap docs with /init. It scans the codebase and writes a starting CLAUDE.md; trim it to the essentials after.
  • Verify, don't assume. Use /qa or /verify to confirm a change works in the real app, not just in theory.
  • Prefer dedicated tools. Skills and built-in tools (Read, Grep, Edit) are cheaper and clearer than ad-hoc shell for the same job.
  • Pick the right model. Heavier reasoning for hard problems; faster/cheaper modes for routine edits.
