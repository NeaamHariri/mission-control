Keep it current

Run /update at the end of a session

Type /update (or /update <project>) in any project session. It refreshes that project's mission-control.md note so tomorrow's dashboard is already current.

  1. Target — defaults to the project you worked on this session.
  2. Note — opens/creates ~/Startups/<project>/mission-control.md.
  3. Frontmatter — bumps status, sets the single most important next, checks off milestones, prunes & adds todos, refreshes the summary.
  4. Regenerate — runs python3 generate.py so data.js reflects the change.
  5. Confirm — prints a one-line diff of what changed.

Only the project you actually worked on is edited, and nothing is invented — only what genuinely happened gets recorded.

Run /update-arch when the architecture changed

Technical knowledge is not touched by /update (which only does status). Run /update-arch (or /update-arch <project>) when the system's real shape or workings changed. It keeps three tiers current:

  1. Diagram — tech-architecture.json (tiers → boxes, nodes with a kind, edges with a flow), rendered live with Cytoscape.
  2. Always-on brief — the Architecture section in the project's own CLAUDE.md (stack, key paths, data flow, commands, gotchas). Loaded every session, so kept tight. Bootstrap with /init.
  3. On-demand spec — knowledge/architecture.md (module map, schema, flows). Featured in full on the project page; Claude reads it only when needed.
  4. Regenerate — runs python3 generate.py; confirms which tiers changed.

Altitude rule: document shape, why & where — never line-level behavior. The code is the source of truth; over-detailed docs rot. Author tech docs only for projects with real code.

Run /update-usage to refresh spend

Claude Code spend is automatic. Every python3 generate.py re-reads the session logs, so token counts are exact as of the last run. The dollar figure is an estimate (Claude logs tokens, not cost), always labelled est.

Higgsfield needs a refresh — generate.py is stdlib-only and can't call MCP. In a session with the Higgsfield MCP connected, run /update-usage:

  1. Calls the Higgsfield MCP balance tool → rewrites higgsfield-usage.json (credits, plan, today as asOf).
  2. Calls the Higgsfield MCP transactions tool (pages with the cursor until exhausted) → rewrites higgsfield-transactions.json with the full list + current balance.
  3. Re-runs python3 generate.py and confirms balance / # transactions / used today·7d·30d.

Renewal dates are derived automatically — Claude from your Stripe subscription anchor, Higgsfield from the latest subscription-credit grant. A natural cadence is to run /update-usage whenever you open Mission Control.

Run /update-news to refresh the news feed

The Claude News page is a curated snapshot, not a live feed — generate.py can't fetch the web. Run /update-news to refresh it in one step:

  1. Searches the web for the latest Anthropic / Claude releases, events, and tutorials.
  2. Rewrites claude-news.json (releases, events, tutorials, sources + today's updatedAt) — only real, sourced items.
  3. Re-runs python3 generate.py and confirms the counts + next upcoming event.

The "Official sources" links on the news page always point to live info, so even a stale feed stays useful between refreshes.

Version control: personal vs team

The files Mission Control writes into each project — mission-control.md, knowledge/, and tech-architecture.json — are personal dashboard state, not shared product code. Whether they belong in git depends on whose repo it is.

  1. Team / shared repo — keep them git-ignored (the default). Teammates don't need your private notes, and committing them just adds noise.
  2. Personal repo — commit them if you like; they travel with the code and back up your status, journal, and diagrams. Your call.
  3. Ignore everywhere by default — add those patterns to ~/.config/git/ignore (git's global ignore). It never untracks already-committed files, so it's safe to add anytime.
  4. Opt one repo back in — un-ignore in that repo's local .gitignore (!mission-control.md, !knowledge/, …) and commit normally.

The /update and /update-arch commands carry this rule, so the agent leaves these files ignored unless you ask to version them. Full details on the How it works page.
